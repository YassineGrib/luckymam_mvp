## User Story
> En tant qu'utilisatrice, je veux une expérience adaptée à mon plan (durée pub ou absence).

## Description
Règles pubs par plan :
- **Standard** : ≥5s non-skippable
- **Freemium** : ≥3s non-skippable
- **VIP** : 0 pub (aucun appel SDK/pub)

Timer contrôlé côté app **+** enforcement côté serveur via entitlements.

## Critères d'acceptation

```gherkin
Scenario: Freemium - 3s minimum
  Given mon plan est Freemium
  When une publicité s'affiche
  Then je ne peux pas la fermer avant 3 secondes

Scenario: Standard - 5s minimum
  Given mon plan est Standard
  When une publicité s'affiche
  Then je ne peux pas la fermer avant 5 secondes

Scenario: VIP - zéro publicité
  Given mon plan est VIP
  When j'utilise l'app
  Then aucune pub ne s'affiche
  And aucun appel au provider/SDK pub n'est déclenché
```

## Sécurité
- Contrôle serveur (entitlements/feature flags) + anti-bypass
- Conformité consentement analytics/ads

## Analytics
`ad_impression` · `ad_timer_started` · `ad_closed` · `ad_blocked_vip`

## Notes
Hypothèse : plans Freemium / Standard / VIP.

## Adaptation du périmètre (2026-06-21 — validée par le client)

Aucun contrat avec une régie publicitaire n'étant signé, le ticket a été
réalisé en **régie interne (« house ads »)** : espaces publicitaires servis
par l'app elle-même, sans SDK tiers. Trois emplacements livrés :
1. Ouverture de l'app (après l'écran sponsors)
2. Interstitiels sur les transitions d'onglets
3. Flux Reels (1 pub / 4 reels)

Mapping des plans réels de l'app : **Gratuit → 5 s** non-skippable ·
**Premium → 3 s** · **VIP → 0 pub**. Spécification complète des formats
(dimensions images/vidéos, safe areas, fréquences) :
[spec_technique_espaces_publicitaires.md](../../specs/spec_technique_espaces_publicitaires.md)
