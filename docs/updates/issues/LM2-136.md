## User Story
> En tant que maman, je veux publier un album en ligne pour le partager.

## Description
Publier un album en générant un lien de consultation **read-only**, sécurisé, révocable et expirant.  
Respecter la confidentialité.

## Critères d'acceptation

```gherkin
Given mon album est prêt
When je clique « Publier »
Then un lien unique est généré
And le lien donne accès à l'album en lecture seule
And je peux désactiver le lien (unpublish)
```

## Sécurité
- URL signée + expiration + révocation
- Pas d'indexation par les moteurs de recherche

## Analytics
`album_published` · `album_link_created` · `album_link_revoked`

## 🚫 Blocage — Infrastructure manquante (2026-06-21)

Luckymam est une **app mobile**, pas un site web. Un « lien de consultation read-only » que n'importe qui peut ouvrir dans un navigateur nécessite une infrastructure qui **n'existe pas encore** dans ce projet :

- `firebase.json` ne déclare aucune cible **Hosting** — rien n'est publié sur le web aujourd'hui.
- `luckymam_web/` (la landing page React) n'a **aucune dépendance Firebase** — elle ne peut pas lire Firestore/Storage.
- Il n'existe **aucune Cloud Function** dans le projet. Or un lien "signé + expirant + révocable" ne peut pas être généré depuis le client Flutter seul : la génération d'URLs signées Firebase Storage nécessite l'Admin SDK côté serveur.
- Les Cloud Functions nécessitent le passage de Firebase à la **formule payante Blaze** (le plan gratuit Spark ne les supporte pas).

**Construire cette fonctionnalité correctement implique donc :**
1. Une nouvelle page web publique (Firebase Hosting)
2. Une ou plusieurs Cloud Functions (génération/validation de token, URLs signées)
3. Le passage du projet Firebase en facturation Blaze
4. Une réflexion produit sur l'exposition de photos d'enfants sans authentification, même avec token

**Questions pour le client avant de démarrer :**
- Le budget/l'infrastructure Blaze (Cloud Functions) est-il validé ?
- Le partage doit-il vraiment être un lien web ouvert à tous, ou un partage limité aux personnes ayant déjà l'app (deep link) suffit-il pour le MVP ?
- Cette fonctionnalité 🔵 *Could Have* doit-elle être priorisée avant LM2-138/LM2-139 (Marketplace) qui sont aussi *Could Have* ?

Ticket laissé en attente de réponse du client plutôt que de construire une infrastructure web + facturation sans validation préalable.
