## User Story
> En tant que future maman, je veux pouvoir créer un dossier pour mon bébé à naître dès la déclaration de grossesse, même si son sexe n'est pas encore connu, avec un thème neutre et un libellé d'attente.

## Description
Faire évoluer le modèle `Child` pour gérer les bébés à naître et les sexes non déterminés :
- `lifecycle`: enum `ChildLifecycle { expected, born }` (par défaut `born`)
- `gender`: support de `ChildGender.unknown` (fallback défensif si absent ou null au lieu de `boy`)
- `expectedDate`: DateTime? (date prévue d'accouchement / DPA)
- `pregnancyId`: String?
- `archived`: bool (pour les grossesses interrompues dont les souvenirs sont conservés)
- Thème de couleur neutre (`AppColors.goldenrod`) si genre inconnu
- Libellé d'âge adapté : « Naissance prévue dans X sem. »
- Dans Firestore : `birthDate: null` et `expectedDate: Timestamp` quand `isExpected`. En Dart, `birthDate` reste un non-null DateTime (égal à `expectedDate`) pour préserver les compatibilités d'appels existants.
- Les calendriers de vaccins, jalons et courbes de croissance ne s'appliquent qu'aux enfants avec `lifecycle == born`.

## Critères d'acceptation

```gherkin
Scenario: Document enfant legacy avec genre manquant
  Given un document Firestore legacy sans genre ou avec gender = null
  When le document est converti en modèle Child
  Then gender est interprété comme ChildGender.unknown
  And la couleur de thème est neutre (goldenrod)
  And l'application ne plante pas

Scenario: Enfant attendu
  Given une déclaration de grossesse
  When un dossier enfant attendu est créé
  Then lifecycle est expected
  And birthDate est null dans Firestore et expectedDate est renseigné
  And le libellé indique « Naissance prévue dans X sem. »

Scenario: Isolation des fonctionnalités post-natales
  Given un enfant au statut expected
  When l'application évalue les vaccins et jalons
  Then aucune échéance pédiatrique n'est générée avant la naissance
```
